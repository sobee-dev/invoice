# BillBuzz v2 — Frontend Build Reference

> **For developers and AI agents building the frontend.**
> Every screen is listed in build order. Each entry covers: what the screen does,
> what it renders, every API call it makes, role restrictions, and edge/empty states.
>
> **Stack:** Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS · Axios  
> **Backend base URL:** `NEXT_PUBLIC_BASE_URL` (e.g. `http://localhost:8000`)  
> **Auth:** Bearer token in `Authorization` header, stored in `localStorage` as `token`  
> **All new features are online-only.** No Dexie, no outbox, no service-worker sync.

## Global Rules

### Layout
- All screens under `/dashboard/*` share the dashboard layout: **Sidebar** (left) + **top bar** (right — user avatar, notifications).
- Sidebar links are role-aware:
  - **All roles:** Dashboard, Receipts, Documents, Customers, Products
  - **Owner only:** Inventory, Reports, Staff
- Auth screens (`/login`, `/register`, etc.) use the minimal auth layout — no sidebar.
- Onboarding screens use their own full-screen centered layout.

### Role Check Pattern
```typescript
const { isOwner, isStaff } = useDashboard(); // from DashboardContext
// owner-only pages: redirect to /dashboard if isStaff
// staff-only pages: redirect to /dashboard if isOwner
```

### API Call Pattern
```typescript
// Every page fetches on mount
const [data, setData] = useState(null);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);

useEffect(() => {
  axios.get('/api/endpoint/')
    .then(res => setData(res.data))
    .catch(err => setError(err))
    .finally(() => setLoading(false));
}, []);
```

### Pagination
All list endpoints use **cursor-based pagination**.  
Response shape: `{ results: [...], next: "cursor_url", previous: "cursor_url" }`  
UI: "Load more" button or infinite scroll — use the `next` URL to fetch the next page.

### Empty States
Every list page must render a friendly empty state (illustration + CTA button) when `results.length === 0`.

### Error States
Every page must handle: network error (show retry button) and 401 (auto-redirect to `/login` via axios interceptor).

## 1. Auth — Login

**Route:** `/login`  
**File:** `app/(auth)/login/page.tsx`  
**Access:** Public (redirect to `/dashboard` if already authenticated)

### What It Does
Entry point for returning users. Supports email/password and Google OAuth.

### UI Components
- Email input
- Password input (with show/hide toggle)
- "Remember me" checkbox
- Submit button ("Sign In")
- Google OAuth button (`<GoogleAuthButton />`)
- Link to `/register`
- Link to `/forgot-password`
- Error message banner (invalid credentials)

### API Calls
```
POST /api/users/login/
  body:    { email, password }
  success: { access, refresh, user: { id, email, role }, business }
  error:   400 → show "Invalid email or password"
```

### On Success
1. Save `access` → `localStorage.setItem('token', access)`
2. Save `refresh` → `localStorage.setItem('refreshToken', refresh)`
3. If `business === null` or `business.onboarding_complete === false` → redirect `/onboarding`
4. Else → redirect `/dashboard`

### States
| State | UI |
|---|---|
| Loading | Spinner on submit button, inputs disabled |
| Error | Red banner below the form |
| Success | Redirect (no visible state) |

## 5. Auth — Google OAuth Callback

**Route:** `/oauth/callback`  
**File:** `app/(auth)/oauth/callback/page.tsx`  
**Access:** Public (Google redirects here with `?code=xxx`)

### What It Does
Receives the OAuth `code` from Google, exchanges it for JWT tokens, then redirects the user.

### UI Components
- Full-screen loading spinner ("Signing you in…")
- Error state ("Something went wrong — try again") with link to `/login`

### API Calls
```
POST /api/auth/google/callback/
  body:    { code }           ← read from URL query param
  success: { access, refresh, user, business, is_new }
  error:   400/401 → show error state
```

### On Success
Same logic as Login success (check `business` + `onboarding_complete`).  
If `is_new === true` → redirect to `/onboarding`.

## 6. Onboarding — Business Info

**Route:** `/onboarding`  
**File:** `app/(protected)/onboarding/page.tsx`  
**Access:** Authenticated, only if `business.onboarding_complete === false`

### What It Does
Step 1 of 2. Collects the owner's business details.

### UI Components
- Progress indicator (Step 1 of 2)
- Business name input (required)
- Business email input
- Phone number input
- Address line 1 + Address line 2 inputs
- Registration number input
- Currency selector (dropdown)
- Tax rate input (percentage) + Tax enabled toggle
- Logo upload (image picker → Cloudinary direct upload → preview thumbnail)
- Signature type selector: None / Text / Draw
  - If Text: signature text input
  - If Draw: `<SignaturePad />` canvas → upload blob to Cloudinary
- Brand colour pickers: Primary + Secondary
- "Continue" button

### API Calls
```
GET  /api/business/me/
  → prefill form if business already partially created

Cloudinary direct upload (logo/signature):
POST https://api.cloudinary.com/v1_1/{NEXT_PUBLIC_CLOUDINARY_CLOUD}/image/upload
  body: FormData { file, upload_preset: NEXT_PUBLIC_CLOUDINARY_PRESET }
  returns: { secure_url }   ← store this, send to backend

PATCH /api/business/me/
  body: {
    name, email, phone, address_one, address_two,
    registration_number, currency, tax_rate, tax_enabled,
    logo_url, signature_type, signature_text, signature_url,
    brand_color_one, brand_color_two
  }
```

### Validation
- Name is required
- If `signature_type === 'text'` → `signature_text` required
- If `signature_type === 'image'` → signature must be drawn
- Phone: 7–15 digits

### On Success
Redirect to `/onboarding/template`.

## 8. Dashboard — Owner

**Route:** `/dashboard`  
**File:** `app/(protected)/dashboard/page.tsx`  
**Access:** Owner role (`user.role === 'owner'`)

### What It Does
Central overview of the business. Shows revenue, outstanding amounts, inventory health, and recent documents.

### UI Components
- **Stat cards (top row):**
  - Monthly Revenue (total confirmed + delivered sales invoices this month)
  - Outstanding Receivables (total unpaid sales invoices)
  - Inventory Value (sum of `quantity_on_hand × unit_price` across all products)
  - Low Stock Alerts (count of products where `is_low_stock === true`)
- **Recent Documents table** (last 5, any type)
  - Columns: Number, Type, Customer, Date, Status, Amount, Payment Status
  - Row click → `/dashboard/documents/{id}`
- **Quick action buttons:** New Document, New Product, New Customer

### API Calls
```
GET /api/reports/dashboard/
  response: {
    monthly_revenue,
    outstanding_receivables,
    inventory_value,
    low_stock_count
  }

GET /api/documents/?cursor=&page_size=5
  → recent 5 documents for the table
```

### States
| State | UI |
|---|---|
| Loading | Skeleton cards + skeleton table rows |
| Error | Retry banner |
| Empty (no documents yet) | Welcome card + "Create your first invoice" CTA |

## 11. Documents — Create

**Route:** `/dashboard/documents/new`  
**File:** `app/(protected)/dashboard/documents/new/page.tsx`  
**Access:** All authenticated users

### What It Does
Creates a new document (sales invoice, purchase invoice, or proforma invoice). Online only — requires server connection to load products and customers.

### UI Components
- **Document type selector** (top of form — changing type adjusts visible fields):
  - Sales Invoice | Purchase Invoice | Proforma Invoice
- **Document metadata:**
  - Document number (auto-suggested, editable)
  - Document date (date picker, defaults to today)
- **Customer section** (sales invoice / proforma):
  - Customer search/select (autocomplete from `/api/customers/`) OR free-text name
  - Customer email, phone (auto-filled if customer selected)
- **Supplier section** (purchase invoice only):
  - Supplier name input
- **Line items table:**
  - Each row: Product picker (optional) | Description | Qty | Unit Price | Total (auto-calc)
  - "Add item" button appends a new empty row
  - Trash icon removes a row
  - If product selected from picker → auto-fill description + unit price
- **Totals panel (right or bottom):**
  - Subtotal (sum of item totals)
  - Tax rate (prefilled from business settings, editable)
  - Tax amount (calculated)
  - Discount input
  - Grand Total (bold)
- **Save as Draft** button + **Save & Confirm** button

### API Calls
```
GET /api/customers/?search=&page_size=20
  → customer autocomplete dropdown

GET /api/products/?is_active=true&search=
  → product picker autocomplete

POST /api/documents/
  body: {
    document_type,
    document_number,
    document_date,
    customer_name,
    customer_email,
    customer_phone,
    customer,              ← uuid (optional, if selected from list)
    supplier_name,         ← purchase invoices only
    subtotal,
    tax_rate,
    tax_amount,
    discount,
    grand_total,
    items: [
      {
        product,           ← uuid or null
        description,
        quantity,
        unit_price,
        total
      }
    ]
  }
  success: { id, ... }
  → redirect to /dashboard/documents/{id}
```

### Validation
- At least 1 line item required
- Grand total must equal `subtotal + tax_amount - discount` (±0.01)
- Document number must be filled

## 12. Documents — Detail / Actions

**Route:** `/dashboard/documents/[id]`  
**File:** `app/(protected)/dashboard/documents/[id]/page.tsx`  
**Access:** All authenticated users (staff only sees documents they created)

### What It Does
Displays a full document. All lifecycle actions are triggered from this page.

### UI Components
- **Document header:** Number, Type badge, Status badge, Date
- **Customer / Supplier info block**
- **Line items table** (read-only unless DRAFT status)
- **Totals panel**
- **Payment info:** Payment status badge, Amount paid, Paid at
- **Timeline / history** (optional, shows status changes)
- **Action buttons** — contextual based on current status:

| Current Status | Available Actions |
|---|---|
| DRAFT | Edit · Confirm · Cancel · Delete |
| CONFIRMED (Sales Invoice) | Deliver · Deduct Inventory · Cancel |
| CONFIRMED (Purchase Invoice) | Deliver · Cancel |
| CONFIRMED (Proforma) | Deliver · Cancel |
| DELIVERED (Sales Invoice) | Deduct Inventory · Mark Paid |
| DELIVERED (Purchase Invoice) | Add to Inventory · Mark Paid |
| DELIVERED (Proforma) | Mark Paid |
| CANCELLED | (no actions) |

- **Deduct Inventory modal** (Sales Invoice only):
  - Option A: "Subtract All" — one click
  - Option B: Per-item table with quantity inputs
  - Confirm button

### API Calls
```
GET  /api/documents/{id}/

PATCH /api/documents/{id}/           ← edit (DRAFT only)

POST /api/documents/{id}/confirm/
POST /api/documents/{id}/deliver/
POST /api/documents/{id}/cancel/
POST /api/documents/{id}/mark-paid/
DELETE /api/documents/{id}/          ← soft delete

POST /api/documents/{id}/deduct-inventory/
  body: { subtract_all: true }
  OR:   { items: [{ item_id, quantity }] }

POST /api/documents/{id}/add-to-inventory/
  body: {}
```

### States
| State | UI |
|---|---|
| Loading | Full-page skeleton |
| 404 | "Document not found" with back button |
| Action in progress | Button spinner, others disabled |
| Action success | Toast notification + status badge updates |
| Action error (e.g. insufficient stock) | Error toast with backend message |

Example pattern:

```typescript
// lib/api/documents.ts
import axios from '@/lib/axios';
import { Document, DocumentItem } from '@/lib/types';

export const getDocuments = (params = {}) =>
  axios.get('/api/documents/', { params }).then(r => r.data);

export const getDocument = (id: string) =>
  axios.get(`/api/documents/${id}/`).then(r => r.data);

export const createDocument = (body: Partial<Document>) =>
  axios.post('/api/documents/', body).then(r => r.data);

export const confirmDocument = (id: string) =>
  axios.post(`/api/documents/${id}/confirm/`).then(r => r.data);

export const deductInventory = (id: string, body: object) =>
  axios.post(`/api/documents/${id}/deduct-inventory/`, body).then(r => r.data);

// ... and so on for every action
```
